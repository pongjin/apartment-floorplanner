# 프로젝트 구현 현황과 인수인계

최종 갱신: 2026-08-31

이 문서는 초기 기획 이후 실제로 구현된 내용과 유지보수 시 알아야 할 결정을 정리합니다. `apartment-floorplanner-mvp-plan.md`는 최초 범위를 설명하는 역사적 문서이며, 현재 동작은 이 문서와 코드를 기준으로 판단합니다.

## 현재 상태

MVP 핵심 흐름인 `도면 → 축척 → 구조 → 가구 → 3D → PNG 저장`이 동작합니다. 모든 프로젝트 상태는 하나의 Zustand 스토어에서 관리되고 Dexie를 통해 브라우저 IndexedDB에 자동 저장됩니다.

## 완료된 작업

### 도면과 축척

- 로컬 JPG/PNG 업로드
- 좋은 도면과 피해야 할 도면을 비교하는 모바일 첨부 가이드
- 해상도·색상 비율·대비·경계선 품질 검사 및 부적합 도면의 다음 단계 진입 차단
- 예시 평면도 로딩
- 기준선 두 점과 실제 mm 입력을 이용한 축척 계산
- 축척 적용 결과를 도면에 표시
- 확대·축소, 트랙패드 이동 모드와 키보드 미세 이동

### 구조 인식과 편집

- 도면 본체 영역, 컬러/선화 유형, 추정 벽 두께를 분리한 휴리스틱 벽 그래프 자동 인식
- AI Hub STR 1,500장으로 전이학습한 LRASPP 모델을 ONNX로 변환해 브라우저에서 문·창 후보 추론
- AI 문은 실제 유한 벽 선분, AI 창은 같은 방향 벽 축에 스냅하는 하이브리드 결합
- 저해상도 입력을 분석 전용 해상도로 정규화하고 원본 축척 좌표로 복원
- 문 열림 호, 개구부 양쪽의 도면 내용, 평행선 단서를 함께 사용하는 일반문·창 후보 분류
- 분리된 도면 행 영역을 연결해 상·하부 구조 누락을 줄이고 도곽 영역은 제외
- 여닫이문·미닫이문·기타문·여닫이창·미닫이창·기타창 AI 후보와 확률 표시
- 베란다문은 수동 생성 도구로 제공
- 창문 후보를 파란 점선, 문 후보를 빨간 점선으로 구분
- 자동 인식 벽과 사용자 생성 벽을 녹색 계열 점선으로 표시
- 기존 구조 수정 / 신규 구조 생성 모드 분리
- 독립된 두 점 단위로 벽 생성 및 생성 취소
- 일반문, 창문, 미닫이문, 베란다문 수동 생성
- 벽과 개구부 선택·삭제

### 가구 배치

- 침실, 거실, 수납, 테이블, 의자, 서재, 주방, 가전, 컴퓨터, 조명, 식물, 장식 카테고리
- 120개 이상의 파라메트릭 프리셋
- 사용자 이름·가로·세로·높이·색상 입력을 통한 사용자 가구 생성
- 20개 기본 색상 프리셋과 세부 RGB 선택
- 이동, 회전, 복제, 삭제, 치수와 색상 수정
- 벽 두께 바깥면 기준의 엄격한 스냅 및 코너 두 면 정렬
- 방향키 50mm 미세 이동

### 3D

- 벽 높이와 두께 반영
- 일반문, 창문, 미닫이문, 베란다문별 시각 표현 및 벽 개구부
- 가구 유형과 shape에 따른 간소화 파라메트릭 모델
- 선택 가구 근처 직접 조작 UI
- 2D 평면 자유 이동과 3D 높이 이동 분리
- 90도 회전, 삭제, 좌표·높이·색상 직접 수정
- 카메라 궤도 회전, 확대·축소, 화면 기준 시점 이동
- 모바일 한 손가락 시점 이동과 축소된 조작 패널
- 마지막 카메라 위치와 target 저장

### 저장

- 원본 도면 위 구조·가구를 합성한 전체 2D PNG
- 현재 WebGL 카메라 시점의 3D PNG
- 모바일 Web Share API 공유창과 미지원 환경의 PNG 다운로드 대체 처리
- JSON, PDF 등 편집 데이터 내보내기는 제품 요구에 따라 제공하지 않음

## 핵심 데이터 흐름

```text
FloorPlanImage (px)
        │
        ▼ calibration.mmPerPixel
Project geometry (mm) ───────► React Konva 2D
        │
        ▼ mm / 1000
Three.js scene (meter) ──────► Current-view PNG
```

- 편집 좌표와 치수의 source of truth는 millimeter입니다.
- 이미지 픽셀 좌표는 축척 보정과 화면 변환에만 사용합니다.
- Three.js에서는 `project.x → scene.x`, `project.y → scene.z`, 높이와 elevation은 `scene.y`로 변환합니다.

## 중요한 구현 결정

1. **백엔드 없음**: 인증과 서버 저장 없이 브라우저 로컬 저장을 사용합니다.
2. **자동 인식은 보조 기능**: 인식 결과는 항상 사용자가 수정할 수 있어야 합니다.
3. **실제 상품 모델 미포함**: 저작권·배포 크기·일관성을 고려해 치수 기반 자체 모델을 사용합니다.
4. **개구부 연결 보정**: 독립적으로 그린 개구부도 3D 진입 시 가장 가까운 평행 벽에 연결해 벽을 분할합니다.
5. **3D 가구 높이**: `FurnitureItem.elevationMm`을 별도로 저장하며 기존 데이터에는 `0`을 기본값으로 적용합니다.
6. **이미지 전용 결과물**: 저장 단계는 2D/3D PNG만 제공합니다.
7. **업로드 품질 게이트**: 짧은 변 320px, 긴 변 480px, 15만 화소를 하드 최소 기준으로 삼고 짧은 변 500px 이상 원본을 권장합니다. 선명한 흑백 선화는 허용하며, 흑백이면서 저대비이거나 경계선이 부족한 도면은 재첨부를 요청합니다.

## 개발 시 확인 사항

- 저장 스키마에 optional 필드를 추가해 기존 IndexedDB 데이터와 호환성을 유지합니다.
- 도면 화면의 좌표는 pan/zoom이 적용되므로 포인터 좌표를 바로 mm로 저장하지 않습니다.
- 3D 직접 이동은 첫 native pointer move를 기준점으로 사용해 트랙패드·고해상도 화면에서 좌표가 튀지 않게 합니다.
- 새로운 개구부 종류를 추가할 때 2D 렌더링, store 생성 action, `resolveOpenings`, `Opening3D`를 함께 수정합니다.
- 가구 shape를 추가할 때 프리셋 타입 union과 `Furniture3D` 모델 분기를 함께 확인합니다.

## 알려진 기술 부채

- 3D 번들이 크므로 현재 Vite 빌드에서 500kB 초과 경고가 발생합니다. 기능에는 영향이 없지만 lazy loading 후보입니다.
- 벽은 휴리스틱 기반이므로 가구선·치수선이 많은 흑백 도면에서 과검출될 수 있습니다. AI 문·창도 공급처·해상도 차이에 따라 오탐이 남으므로 사용자 검토가 필요합니다.
- 첫 자동 인식은 모델·WASM 약 24MB 다운로드와 모바일 CPU 추론 때문에 이후 실행보다 오래 걸릴 수 있습니다.
- ESLint 의존성은 있으나 flat config가 아직 없어 `pnpm lint`를 정식 품질 게이트로 사용하지 않습니다.
- 현재는 단일 최신 프로젝트만 복원하는 흐름이며 프로젝트 목록 UI가 없습니다.
