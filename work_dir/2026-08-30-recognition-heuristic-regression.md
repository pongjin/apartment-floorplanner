# 업로드 기준 완화 및 자동인식 회귀 개선

- 날짜: 2026-08-30
- 관련 커밋: 이 기록을 포함하는 커밋
- 커밋 제목: `fix: improve floor plan upload and opening detection`

## 배경과 목표

기존에 인식되던 720×527px 예시 도면이 강화된 업로드 품질 기준에 막혔고, 큰 도면에서 도면 본체를 한 개의 행 영역으로만 선택해 상단 구조가 잘리는 문제가 있었습니다. 또한 평행선만으로 미닫이문을 추론하면서 창이 미닫이문 후보가 되고, 외곽 여부를 인식 영역의 최솟값·최댓값으로 판정해 일반문이 창으로 바뀌는 회귀가 발생했습니다. 업로드 기준을 현실적으로 완화하고 자동 인식 범위를 벽·일반문·창으로 명확히 제한하는 것이 목표입니다.

## 변경 내용

- 업로드 하드 최소 기준을 짧은 변 320px, 긴 변 480px, 15만 화소로 완화하고 짧은 변 500px 이상을 권장 기준으로 표시
- 선명한 흑백 선화는 허용하고 흑백이면서 저대비이거나 경계선이 부족한 경우에만 재첨부 요청
- 도면 본체 탐색에서 가까운 복수 행 영역을 연결해 상단과 하단 구조를 함께 분석
- 문 열림 호 탐색 반경을 확대하고, 개구부 양쪽의 실제 픽셀 내용을 이용해 실내 일반문과 외벽 창을 구분
- 자동 후보에서 미닫이문과 베란다문을 제거하고 확신할 수 없는 후보는 생성하지 않도록 변경
- 소개 문서와 구현 현황의 품질 기준 및 자동인식 범위를 현재 코드에 맞게 갱신
- OpenCV 도입 기대 효과, 평가 기준, 단계별 라벨링 규모를 자동인식 고도화 문서로 정리

## 영향

- 기존 예시 도면은 다시 업로드할 수 있습니다.
- 선명한 흑백 도면도 편집 흐름에 들어갈 수 있지만 컬러 원본 권장은 유지됩니다.
- 자동 인식은 벽·일반문·창만 생성하며 미닫이문과 베란다문은 사용자가 수동으로 추가합니다.
- 프로젝트 저장 스키마와 기존 수동 편집 기능에는 변경이 없습니다.

## 검증

- 390×844 모바일 브라우저에서 실제 파일 업로드와 자동 인식을 반복 검증
- `sample_map.png`: 벽 17개, 일반문 2개, 창 1개, 미닫이문 후보 0개
- 대형 회귀 도면: 벽 26개, 일반문 2개, 창 0개로 상단 거실·주방 구조 복원 및 도곽 제외 확인
- 대형 회귀 도면에서 눈으로 확인되는 일반문 약 5개 중 2개가 후보가 되어 문 후보 재현율의 잔여 한계를 확인
- 모바일 가로 넘침과 브라우저 콘솔 오류 없음
- 번들된 Node.js로 TypeScript 빌드와 Vite 프로덕션 빌드 통과
- `git diff --check` 통과

## 남은 한계

- 현재 개구부 후보는 같은 축의 벽 선분 사이 틈에서만 만들어집니다. 벽선이나 문 기호가 끊기거나 가구선과 겹치면 분류 전에 후보 자체가 누락될 수 있습니다.
- OpenCV 형태학 처리와 확률적 허프 변환으로 구조선 연결과 후보 생성 재현율을 높인 뒤, 별도 평가 세트에서 정밀도·재현율을 측정하는 후속 작업이 필요합니다.
- 다양한 국내 부동산 도면에서 문과 창 의미 분류를 안정화하려면 전이학습 모델과 현지 도면 라벨이 필요합니다.
