# 모바일 도면 제어 배치 보정

- 날짜: 2026-09-01
- 관련 커밋: 이 기록을 포함하는 커밋
- 커밋 제목: `fix: refine mobile floor plan controls`

## 배경과 목표

모바일 헤더에서 프로젝트 초기화 문구가 버튼 폭을 벗어나 세로로 줄바꿈되고, 도면 이동 버튼이 도면 위쪽을 불필요하게 가리고 있었다. 또한 벽 자동 인식 결과가 단계 제목 안에서 이전·다음 버튼과 공간을 경쟁하므로 관련 기능인 자동 인식 버튼 가까이 옮길 필요가 있었다.

## 변경 내용

- 초기화 버튼을 명시적인 가로 flex 레이아웃과 줄바꿈 방지 스타일로 변경하고 모바일에서도 내용에 맞는 폭을 유지하도록 했다.
- 도면 이동 버튼을 확대·축소 컨트롤의 `맞춤` 버튼 바로 왼쪽으로 옮겼다.
- 도면 이동 버튼 배경을 반투명하게 바꾸고 블러·채도 효과를 적용해 아래 도면이 비치도록 했다.
- 벽·개구부 결과 카드를 단계 제목에서 제거하고 하단 자동 인식 버튼 바로 오른쪽에 배치했다.
- 결과 카드를 모바일 하단 도구 모음 높이에 맞춰 축소하고 벽·개구부 수를 함께 표시했다.

## 영향

- 작은 모바일 화면에서도 `초기화` 문구가 아이콘 옆 한 줄로 표시된다.
- 도면 이동과 화면 맞춤 기능이 한곳에 모여 관련 제어를 더 쉽게 찾을 수 있고, 도면 가림이 줄어든다.
- 자동 인식 결과가 실행 버튼 옆에서 즉시 확인되며 단계 제목 영역이 단순해진다.
- 프로젝트 저장 데이터와 자동 인식 로직에는 변경이 없다.

## 검증

- `node node_modules/typescript/bin/tsc -b`: 성공.
- `node node_modules/vite/bin/vite.js build`: 성공. 2,324개 모듈 변환과 프로덕션 번들 생성을 확인했다.
- 로컬 브라우저를 390×844로 설정해 다음을 확인했다.
  - 초기화 아이콘과 문구가 헤더 우측에서 한 줄로 표시됨.
  - 도면 이동 버튼과 맞춤 컨트롤의 상단 좌표가 동일하고 도면 이동 버튼이 맞춤 컨트롤 왼쪽에 위치함.
  - 도면 이동 버튼에 반투명 배경과 `backdrop-filter`가 적용됨.
  - 제목 영역에 결과 카드가 없고 하단 도구 모음 자식 순서가 `전체 삭제 → 한 단계 취소 → 자동 인식 → 벽·개구부 결과`임.
  - 화면 가로 넘침 없이 벽 편집 화면이 표시됨.
