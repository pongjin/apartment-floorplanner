# 도면 편집·가구 조작 UX 개선

- 날짜: 2026-09-01
- 관련 커밋: 이 기록을 포함하는 커밋
- 선행 구현 커밋: `f723967` (`feat: improve floor plan and furniture UX`)
- 커밋 제목: `feat: refine editing and furniture controls`

## 배경과 목표

도면 편집과 가구 배치의 핵심 기능은 동작했지만, 작업 모드와 실제 제스처가 어긋나거나 조작 버튼이 콘텐츠를 가리는 문제가 있었다. 특히 벽 단계의 한 단계 취소가 자동 인식 결과까지 훼손하지 않도록 범위를 분리하고, 축척 정보·단계 이동·가구 속성처럼 반복해서 사용하는 제어를 각 단계의 맥락에 맞게 재배치하는 것이 목표였다.

## 변경 내용

- 선행 구현(`f723967`)
  - 3D 평면 이동 좌표를 화면 포인터 방향에 맞추고 드래그 중 즉시 반영되도록 수정했다.
  - 2D·3D 가구에 평면 이동, 높이 이동(3D 전용), 90도 회전, 제거, 속성 제어를 추가하고 상세 위치·크기·색상은 속성 버튼을 눌렀을 때만 표시하도록 정리했다.
  - 이미지 업로드 뒤 빈 여백을 자를 수 있는 크롭 단계와 축척 설정 안내 팝업을 추가했다.
  - 가구 라이브러리 폭 조절 손잡이를 추가하고 폭을 사용자 설정으로 유지하며, 라이브러리의 3D 보기 버튼은 제거했다.
  - 도면 확대·축소를 도면 이동 모드에서만 허용하고, 새 벽·문·창 끝점을 주변 구조에 스냅하도록 보정했다.
  - 슬라이딩 도어와 베란다 창을 3D에 구현하고 `베란다 문` 명칭을 `베란다 창`으로 통일했다.
  - 헤더 새로고침 아이콘에 `초기화` 문구를 추가하고 모바일 작업 영역을 더 넓게 쓰도록 단계별 높이와 패널 배치를 다듬었다.
- 이번 보완
  - 벽·개구부 사용자의 추가, 수정, 삭제 작업만 최대 50단계까지 메모리에 기록하고 `한 단계 취소`가 마지막 사용자 작업만 복구하도록 변경했다. 자동 인식 결과를 적용할 때 기록을 새 기준점으로 비워 자동 인식 벽은 취소 대상에 포함하지 않는다.
  - 축척 표시는 캔버스 이미지에 그리지 않고 벽 편집 단계 좌측 상단의 HTML 카드로 옮겼으며 다른 단계에서는 숨긴다.
  - 3·4·5단계 제목 카드 우측에 이전·다음 버튼을 배치하고 단계별 진행 조건을 연결했다.
  - 2D 속성에 `크기 세부 조정`, `색 변경`, 3D 속성에 `위치 세부 조정`, `크기 세부 조정`, `색 변경` 소제목을 추가했다. 색상 목록은 가로 스크롤바를 항상 노출한다.
  - 3D 직접 조작 버튼을 44px(모바일 38px)의 반투명 글래스 버튼으로 줄이고 가구 중심을 비우는 오각형으로 배치했다. 속성 패널을 열면 직접 조작 버튼을 숨겨 패널을 가리지 않도록 했다.
  - 좁은 화면에서 3D 캔버스의 최소 콘텐츠 폭이 작업 영역을 1100px로 확장하던 문제를 수정해 390px 화면에서도 단계 이동과 속성 패널이 화면 안에 유지되도록 했다.

## 영향

- 자동 인식된 벽과 개구부는 `한 단계 취소`로 제거되지 않는다. 자동 인식 후 수동으로 추가·수정·삭제한 작업만 역순으로 복구된다.
- 취소 기록은 저장 프로젝트 스키마를 바꾸지 않는 메모리 상태이므로 기존 IndexedDB 프로젝트와 호환된다.
- 축척 카드와 단계 이동 버튼은 해당 작업 단계에서만 보여 캔버스 위의 상시 오버레이를 줄인다.
- 가구 상세 패널은 필요한 순간에만 열리며, 모바일에서도 가로 넘침 없이 사용할 수 있다.

## 검증

- `node node_modules/typescript/bin/tsc -b`: 성공.
- `node node_modules/vite/bin/vite.js build`: 성공. 2,324개 모듈 변환과 프로덕션 번들 생성을 확인했다.
- `node node_modules/eslint/bin/eslint.js .`: 실행했으나 ESLint 9가 요구하는 `eslint.config.js`가 저장소에 없어 검사 시작 전에 종료됐다.
- 데스크톱 로컬 화면 검증:
  - 3·4·5단계 제목 우측의 이전·다음 버튼과 벽 단계 축척 카드를 확인했다.
  - 2D 속성 소제목 두 개와 색상 행의 `overflow-x: scroll` 및 `scrollWidth 684 > clientWidth 355`를 확인했다.
  - 3D 속성 소제목 세 개와 색상 행의 `scrollWidth 607 > clientWidth 274`를 확인했다.
  - 3D 직접 조작 버튼 다섯 개가 서로 다른 오각형 좌표에 44px 크기로 배치되고 `backdrop-filter: blur(9px) saturate(1.2)`가 적용됨을 확인했다.
- 모바일 390×844 화면 검증:
  - 작업 영역과 제목 카드 폭이 390px로 유지되고 페이지 가로 넘침이 없음을 확인했다.
  - 이전·다음 버튼과 374px 폭의 3D 속성 패널이 화면 안에 표시됨을 확인했다.
- 프로덕션 미리보기 검증:
  - 예시 도면 자동 인식 결과 17개 벽과 8개 개구부가 생성된 직후 `한 단계 취소`가 비활성임을 확인했다.
  - 수동 벽 하나를 추가하면 18개로 증가하고 취소가 활성화되며, 취소 후 자동 인식 기준인 17개 벽·8개 개구부가 유지되고 다시 비활성화됨을 확인했다.

## 남은 한계

- 벽 작업 취소 기록은 브라우저 메모리에만 최대 50개를 유지하므로 새로고침하거나 프로젝트를 다시 불러오면 초기화된다.
- 현재 저장소에 ESLint 9 형식 설정 파일이 없어 `lint` 스크립트를 사용할 수 없다. 별도 설정 마이그레이션이 필요하다.
- 프로덕션 번들은 정상 생성되지만 메인 JavaScript 청크가 약 1.60MB라 Vite의 500kB 청크 크기 경고가 남아 있다. 후속 작업에서 3D·인식 모듈의 추가 코드 분할을 검토할 수 있다.
